# 懸浮操作 v1.0.33：5893 診斷回報、主 App 自動縮小與現場 OCR 裁切預覽

## 5893 截圖確認
- `畫面擷取正常：324 張影格`：表示 MediaProjection 至少有返回影像，**並不證明框內影像是影片字幕**。
- `OCR 成功 324、失敗 0`：代表 OCR 任務有完成，**並不證明有辨識到字幕**。
- `目前 OCR 原始 0 行，有效 0 行`：是進診斷頁面後最近影格的結果；當畫面從 YouTube 換成《懸浮操作》，框選座標依然固定在相同螢幕位置，可能剛好落在沒有文字的 App 位置。舊的 `4:07:02 / 11:54:46 Final reflections >` 代表先前抓過 YouTube 影片的播放控制文字，不能證明原字幕的辨識。
- 翻譯模型已就緒、語音補位未啟用：不用再盲目更換翻譯模型。
- **另一個明確 Bug**：《懸浮操作》在 `onResume` 呼叫 `maybeReturnHome()`，前鏡頭與傳檔的自動退背景邏輯導致進主頁查看診斷後頻繁縮小。

## 本次修復
1. **主 App 不再自動縮小**：只要懸浮翻譯服務正在執行，`maybeReturnHome()` 以及它已排定的 900 ms 延遲回調都不會再把 App 退到背景。新開翻譯時授權成功後仍會有一次主動退背景，讓使用者回原影片框選，維持先前操作體驗。
2. **「譯」懸浮小球新增「檢查字幕畫面」**：不用跳回主 App，直接在當前播放的 YouTube／瀏覽器／動漫畫面點小球，可以叫出一個現場診斷面板。
3. 面板直接顯示**真正送進 ML Kit OCR 的裁切影像縮圖**（最多 650px 寬，只放記憶體），而不只文字形式的框選座標；可確定 OCR 到底看到影片台詞、空白、黑畫面、控制列還是別的內容。
4. 同時保留最近一次有文字的 OCR 原文及距離上次成功辨識文字的秒數，即使後續畫面換成 App 或顯示暫停，之前的非空紀錄也不會被 0 行覆蓋。
5. 開啟現場面板期間**暫停 OCR 擷取和翻譯顯示**，避免自己的面板被重複辨識；關閉恢復原本狀態。
6. **方便回報**：面板可由使用者主動截圖分享以排查。只有使用者自己截圖才會留下外部檔案，App 不會存圖到相簿或上傳任何影格。
7. 保留原版的英／日離線語音補位、手動字幕框、字幕懸浮小球、手勢、Nearby、NFC，不新增其他權限。
8. 原套件 `tw.airgesture.transferbeta`、正式簽章不變；ARM64 精簡 APK `versionCode 46`, `versionName 1.0.33` 可直接覆蓋 1.0.32。

## S26 Ultra 重測步驟
1. 安裝 v1.0.33，翻譯來源選英文，**暫時關閉語音補位**。
2. 進入 YouTube 播放有明確英文字幕的影片，框選原字幕位置按「完成框選」。
3. 如仍只顯示「等待框內字幕…」，**不要切回主 App**；直接點旁邊「譯」浮球 →「檢查字幕畫面」。
4. 對現場診斷面板截圖，確定縮圖內看得到英文字，且看看 OCR 最近一次原文是什麼；回傳這張現場截圖。
5. 點「關閉診斷，繼續翻譯」回影片。再點主 App 圖示確認不會自行縮小，並確認 NFC／手勢／傳檔正常。
6. 如縮圖全黑或全空白，問題在實際擷取影像或字幕框座標，應調查 MediaProjection／WindowManager 而非繼續提高文字辨識倍率。
7. 如果縮圖有清楚的英文字幕，但 OCR 最近一筆始終顯示 0 行，下一步針對 ML Kit 處理與影像 Bitmap 格式；若 OCR 原文正確而中文字幕不更新，檢查翻譯 callback 與字幕顯示元件。

## 仍需實機確認
GitHub CI 通過僅證明編譯、單元測試、簽章與 ARM64 APK 完整。新設計讓使用者能直接取得 OCR *實際裁切影像* 作為關鍵證據，但不保證無須實測便能完全修復文字辨識。
