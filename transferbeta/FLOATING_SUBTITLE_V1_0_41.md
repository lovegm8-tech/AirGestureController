# 懸浮操作 v1.0.41｜即時字幕穩定性與熱量管理

在已通過 CI 的 v1.0.40「逐句快譯、OCR 和語音共用 Qwen」基礎上迭代，並非重寫隔空操作、Nearby 與 NFC。

## 此次處理的實機問題
- **第一行偶爾卡住、第二行不斷變動**：此前只靠 Vosk 的斷句或固定時間切分，語音短暫停頓有時無法及時定稿。
- **下一句已開始才顯示上一句**：v1.0.40 已把穩定片語提早切出、提升 360ms 部分辨識、減少字幕翻譯等候；v1.0.41 在此基礎上加入停頓偵測。
- **擔心 S26 Ultra 長時間發熱或卡頓**：Vosk 和影片播放器需常駐，Qwen 應只當離線補充校對，不該占據全部 CPU 時間。

## v1.0.41 變更
1. **極輕量近靜音偵測**：在 Vosk 讀取到的 16kHz 單聲道 PCM 上，間隔抽樣計算近似平均絕對振幅，連續近靜音約 **780 毫秒**才呼叫 `SubtitleSpeechChunker.onQuiet()`，讓目前已辨識的片語以原 ID 定稿。此機制沒有獨立神經 VAD 模型，也不暫停、不重啟 Vosk；如果影片一直有背景配樂，VAD 可能不會觸發，則沿用 v1.0.40 的**約 1.45 秒以上且具足夠詞數時拆分過長片語**。
2. **不要重複顯示句子**：已因停頓定稿的片語，Vosk 稍後給出的相同 final 不重播，也**不額外跳過一個 subtitle ID**；下一個辨識片語自然填入下一行，第三句上捲。
3. **限制 Qwen 負載**：本地 Qwen 每至少 **7 秒**才接受下一個新的 AI 潤飾請求，保留原本**最新一句優先、單一推論執行緒**。不等待 Qwen 才顯示翻譯，ML Kit 已翻譯的文字一直可見。
4. **原文優先潤飾**：Qwen prompt 明確要求以 Vosk/OCR 的英文、日文或韓文原文為主，機翻初稿僅為可能出錯的參考，不能複製錯誤；前一句只做語境參考。
5. **保留現有功能**：已測 v1.0.40 的語音/OCR 字幕共用本地 Qwen、兩行上捲、不在舊句遲到時重新插入、手動縮小主 App、NFC / Nearby / 手勢不變；Qwen 模型下載已支援手機熱點、行動數據及檔案離線匯入。
6. **版本與簽章**：`versionName=1.0.41`、`versionCode=54`，原套件 ID `tw.airgesture.transferbeta`、原正式簽章金鑰、ARM64 APK，安裝時可覆蓋 v1.0.38 / v1.0.40。

## 實機驗證
- 測試英文快速對話、連續不間斷對話、明顯停頓約 1 秒的句子，以及背景音樂偏大的影片。
- 停頓時，既有片語轉為 final，同一行可讓 Qwen 修正；下一句開始新的行，不可將舊句再插入。
- 觀察畫面上方的第一行有無長時間卡住，以及長影片播放中的翻譯延遲。
- 比較開啟／關閉 Qwen 的翻譯延遲、5～15 分鐘內的發熱、S26 Ultra 多開其他 App 時的流暢度。
- 不以某個特定 °C 降溫或 0.5 秒字幕為保證；實際效能高度取決於背景音樂、音訊來源、音量、手機溫度與語音辨識內容。

## 診斷限制
Vosk 的輸出時間不等於影片音訊真正開始講該句的時間，所以現有診斷可以精確看到 ML Kit 佇列／翻譯耗時，但不能單靠它推算「音訊開始說話 → 字幕出現」的總秒數。實際總延遲要同步錄製聲音與字幕對照。
