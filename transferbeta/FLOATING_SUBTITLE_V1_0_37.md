# 懸浮操作 v1.0.37：中文翻譯固定兩行，第三句上捲第一句

## 使用者指定的顯示規則
- 第一句翻譯顯示在**第一行**。
- 第二句翻譯顯示在**第二行**，第一句保留。
- **第三句**進來時，刪掉舊的第一句，第二句上移至第一行，第三句寫入第二行。
- 始終**最多兩行**；之後每句都按相同方式往上遞補。
- **同一句辨識修正不算新句**：現有 v1.0.36 的 Vosk 每約 520 ms 取得穩定部分文字，待完整句 finalized 後可能更準確。部分字幕與完整句使用同一個 `utteranceId`，回填同一行翻譯，不能新增第三行。
- OCR 自動備援在取得不同畫面原文時也使用相同的兩行顯示規則。

## 程式變更
1. 新增純 Java `SubtitleTwoLineBuffer` 儲存最多兩組來源句子的識別鍵與繁體中文譯文；更新相同識別鍵只修正原行，收到第三個不同識別鍵就上捲，太舊的延遲聲音結果不允許重新插入。
2. 把原本只顯示單段中文字幕的 `captionView TextView` 改為 `LinearLayout` 內兩個**獨立且單行**的 TextView。第二句還沒出現時只顯示第一行，不硬塞空的第二行。設單行自動縮字 18sp 至 12sp，過長時以省略符號表示；**長句不會換行佔用第二句的行**。
3. 保留字幕框拖曳，調整兩行後的高度量測、影片字幕上方位置、語音字幕 68% 高度預設位置；`WindowManager.FLAG_SECURE`、前鏡頭手勢／NFC／Nearby 不變。
4. Vosk 偵測同一個 utterance 的 stable partial 與 final 時，傳遞同樣 `utteranceId`；每個 final speech segment 才將下一句 ID +1，翻譯器的非同步結果使用該 ID 更新正確顯示行。
5. 翻譯狀態（如等待文字、模型下載）不再覆蓋已有的兩行中文字幕；按暫停可顯示暫停提示，恢復後會恢復最近兩句，避免字幕因提示字串閃爍。
6. 依然保留 v1.0.36 的 520 ms 語音暫時片段檢查、約 750 ms 字幕顯示節奏、語音優先／OCR 備用、ML Kit 離線繁中翻譯及原診斷功能。
7. 沿用 v1.0.34 的**唯一主 App 縮小途徑**：只有使用者按「返回桌面 · 開始使用」才會離開主 App，沒有自動縮小。
8. 版本 **1.0.37 / versionCode 50**，ARM64 APK、套件 `tw.airgesture.transferbeta` 與永久簽章均不變，可直接覆蓋上一版本。

## 實機驗證
1. S26 Ultra 覆蓋更新，英文／日文語音優先模式播放連續 3–4 句的 YouTube 影片。
2. 第一句出第一行，第二句出第二行；第三句確認第一句消失、第二句移至第一行、第三句在第二行。第四句同樣上捲。
3. 一句話說到一半若辨識結果修正，僅同一行更新，不應把它誤判成下一句。正式 final 完整句翻譯也應修正同一行。
4. 特別長的一句英文／日文翻譯不能被畫面強制折成兩行而把第二句擠掉；字幕可適度縮字，極長會末端省略。
5. 暫停／恢復、螢幕轉向、OCR 備援、語音音訊授權、調整字幕框、拖曳兩行字幕、新舊文字相同的句子連續出現、主 App 不自行縮小均需測試。
6. GitHub CI 的 JVM 單元測試驗證兩行上捲、同句修正、不顯示第三行、OCR 共用、遲到舊句被忽略、重複/空字幕忽略以及永久簽章。

## 限制
- 這版重點在字幕**呈現與同句修正**，沒有更換 Vosk 小模型或 ML Kit 翻譯引擎；不保證中文語意明顯更自然。語音辨識偶爾把一段話誤分成兩個 final segment，仍可能造成多次上捲，需 S26 Ultra 實際影片測試。
- 當一句中文超過目前字幕區寬度、縮字仍放不下時，會在該行末端省略而**不換行**；這是「一句只能佔一行」的取捨。
