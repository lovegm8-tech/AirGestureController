# 懸浮操作 v1.0.32 — 5891 實測 OCR 停在「等待框內字幕」＋ ARM64 瘦身

## 實測
使用者 S26 Ultra 回報 v1.0.31 直向 YouTube 英文影片字幕沒有更新，提供 5891.mp4（約 10.7 秒手機外拍）。
畫面顯示手動綠框包在真正的英文字幕附近，按下「完成框選」後出現「等待框內字幕…」；稍後影片原字幕
`I know, it's good.` 仍顯示，但中文沒有變化。從外拍無法辨認是 MediaProjection 回傳空白、
OCR 原文 0 行、語言過濾錯誤、翻譯模型未就緒或 OCR 非同步錯誤。
本版不再無依據宣稱某個原因一定是根本原因。

## 修正
1. **OCR 即使翻譯模型還沒載入也先執行**：之前 frameLoop 遭 modelReady=false 擋住，導致遇到模型下載問題時無法確認 OCR 是否本來就能辨識字幕；現在拆開兩個環節。
2. **手動字幕框周邊容錯**：自選區域在螢幕內每側增加少量安全邊界，避免字幕字形因不準確的四角框截斷；針對小字以 2.25–2.7 倍取樣辨識，而不再只用 1500/框寬計算，常見寬框以前只有 1.2–1.4 倍。
3. **字幕掃描間隔從 1000 ms 降為 650 ms**：提高快速字幕被 OCR 看到的機率；仍由 busy guard 防止非同步堆積任務。
4. **加入分階段本機 OCR 診斷**：實際擷取影格數與是否持續有影格、框選原始／實際像素座標、OCR 成功與錯誤次數、OCR 所有文字行數、符合語言篩選的文字行數、翻譯模型就緒／下載失敗狀態、字幕來源選取與語音補位結果。
5. **非同步錯誤可見**：OCR recognizer 完成後如果內部文字解析拋出異常，記錄到診斷狀態而不是默默沒有翻譯；擷取錯誤亦記錄例外類別。
6. **APK ARM64-only**：保留 Samsung S26 Ultra / S25 使用的 `arm64-v8a` 原生函式庫，移除 APK 內用不到的 32-bit ARM 和 x86/x86-64 ABI；其它功能程式保留。此專用 APK 不支援僅 32 位元處理器的 Android 裝置。
7. **保留所有原有功能**：NFC、Nearby、手勢、字幕編輯框、常駐「譯」小球、英文及日文語音補位。未更動這些核心操作。

## 5891 實機驗證
1. 使用同簽章、同套件 `tw.airgesture.transferbeta` 覆蓋安裝 v1.0.32 (versionCode 45)。
2. 先關掉「英文／日文語音補位」（排除 Vosk 與音訊擷取因素），只開啟 OCR 翻譯。Android 畫面分享選「**整個螢幕**」，不可只選「懸浮操作」。
3. 播放原本 5891 的直向 YouTube 英文影片，在英文字幕附近框選（略留 5–10 px 上下空間），按「完成框選」。
4. 若中文仍一直顯示「等待框內字幕」，請回 App 打開「查看字幕辨識診斷」，拍下所有欄位（畫面擷取／OCR 狀態／成功失敗次數／文字行數／模型狀態）。這次可區分是擷取沒影格、OCR 原文空白、語言篩選還是翻譯模型失敗。
5. OCR 單獨測試成功再開啟英文或日文語音補位；比較實際顯示的字幕／語音結果及延遲。
6. 旋轉橫向並重新框選，測試小球拖曳、暫停／恢復、停止翻譯，最後測 NFC、Nearby 和手勢。

## 限制
- ARM64 瘦身只去掉沒有用到的 CPU 架構，ML Kit、Vosk 及其模型功能不會自動改善；如果字幕本身在 MediaProjection 中不可讀，仍需依診斷處理。
- 錄影只呈現外部畫面，無法直接看到該手機 MediaProjection 的影格及 debug logs，未經 S26 Ultra 實機回歸前保持 draft。
