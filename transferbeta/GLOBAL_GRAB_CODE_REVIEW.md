# 隔空抓取 v0.2.0 — 原始碼審核版

**目前狀態：程式碼原型，尚未編譯 APK，也尚未在 S25 / S26 Ultra 實機驗證。**  
此分支獨立於正在使用的 v0.1.2，不會觸發舊有 APK 工作流程。

## 規劃操作流程

1. 兩支手機各自開啟測試 App、完成 Nearby 的雙方驗證碼配對。
2. 使用者從 App 正面按「啟動全域隔空抓取」，並手動在 Android 設定啟用「隔空抓取」無障礙服務。
3. 前鏡頭長期待命。低頻偵測到手掌後，短時間改為快速推論。
4. 在其他 App 前景做出 **張掌 → 握拳**：
   - Chrome 等支援的瀏覽器若能從網址列讀取**完整、可信**的 http/https 網址，傳送網址。
   - 其他顯示照片或文件的 App 若沒有提供合法授權的原檔 URI，僅在無障礙服務已授權時擷取**畫面 PNG 截圖**；**不冒充原檔**。
   - YouTube 原生 App **不依標題推測連結**：尚需研究如何可靠地取得實際分享網址。
5. 接收端做出 **握拳 → 張掌**。接收原檔的 Nearby + SHA-256 驗證流程沿用原有程式；瀏覽器網址由獨立的訊息協定送出。
6. 接收端 App 在前景時直接開啟連結；在其他 App 前景時使用 Android 通知讓使用者點擊開啟，避免依賴受限制的背景 Activity 自動啟動。

## 省電策略

- **ECO：** AI 推論每 950ms 最多一次（約 1 次／秒）。
- **ACTIVE：** 偵測到手掌後，每 115ms 最多一次（約 8.7 次／秒），並維持約 4.5 秒。
- **熄屏：** 解除相機分析綁定；亮屏後僅嘗試恢復服務。
- **鏡頭 FPS：** 只在裝置宣告支援 15FPS 以下的 AE 範圍時，才提出低 FPS 請求；不保證所有機型可用。
- **自願停止：** 前景常駐通知提供停止按鈕。

**重要：推論頻率低不等於相機感光元件低耗電。無法在 Android 一般第三方 App 上保證全天 24 小時超低電量。** 必須在兩款實機量測總耗電及系統是否終止服務。

## 已完成的程式碼檢查

- 使用純 Kotlin 編譯器，在容器中執行 19 個獨立政策檢查：**PASS**。
- 測試包括 ECO / ACTIVE 切換、螢幕關閉、網址完整性檢查、拒絕 \`file:\` / \`javascript:\`、不把原生 YouTube 的標題視為網址。
- GitHub 上另提供 JUnit 原始碼測試，**尚未啟動 Gradle Android 編譯**（依使用者要求）。

## 上 APK 前必須解決或驗證的項目

1. Gradle / Android Manifest 與 CameraX / AccessibilityService 的編譯與執行時相容性。
2. 三星 S25 / S26 Ultra 雙機同時在別的 App 前景時，前鏡頭服務與 Nearby 連線是否存活。
3. 裝置前鏡頭實際待機 FPS、耗電量、發熱、辨識率及誤觸率。
4. 三星相簿 / Google 相簿 / PDF 的截圖效果與受保護畫面拒絕機制。
5. Chrome / Samsung Internet / YouTube App 的網址實際可取得程度。
6. 背景接收後直接開啟連結：Android 受限時需通知點擊，目前不保證完全免點擊。
7. 原本 Nearby 連線暫由 Activity 管理，若 Activity 被銷毀可能斷線；長期運作前應移到持久前景服務。
8. 與既有「隔空操作」App 不能同時佔用前鏡頭，合併前應先解決攝影機資源競爭。
