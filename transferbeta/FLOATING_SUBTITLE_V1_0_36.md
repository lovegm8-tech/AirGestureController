# 懸浮操作 v1.0.36：語音翻譯低延遲優化

## 使用者回報與原因

S26 Ultra 實測 v1.0.35 的「英文／日文語音優先、OCR 備用」翻譯品質比以前好，但中文字幕速度略慢。
程式碼證實至少兩個固定等待：
- Vosk `SubtitlePlaybackSpeech` 以前每 **2,900 ms** 才從進行中的語音取一次 partial hypothesis（暫時辨識文字），即使聲音辨識在進行中。
- `SubtitleVoicePriority.mayDisplayVoice` 過去禁止顯示前一則語音字幕後 1,250 ms 內的任何新語音候選，且 `voiceTranslateBusy` 忙碌時 **直接丟掉**下一則（無排隊），因此部分台詞會漏掉／等到下一個語音邊界才更新。

## 改動
1. Vosk 英文／日文部分文字從每 2,900 ms 降為約 **520 ms** 檢查一次。採用 **`SubtitleSpeechEmissionPolicy`** 比較連續兩次辨識文字共同穩定部分；英文只接受完整單字，日文因文字不以空白切字，接受穩定字串前綴。最小候選英 5 字元、日 3 字元，避免單個聲音片段來回閃。
2. Vosk 說完一句的 final 完整句仍保留，不能因為更快而降低原本完成句的辨識資料。
3. ML Kit 中文翻譯繁忙時改為 **保留最新一筆候選文字**，在前次處理完成後接續翻譯，不再當場丟棄語音。
4. 字幕頻繁刷新改在**顯示端**控制，目標最小間距約 **750 ms**；等待時繼續接受新 ASR 部分結果並合併成最新內容，避免過時字幕排隊越積越多。
5. 字幕診斷新增「語音翻譯耗時」，顯示從 ASR 文字送至 ML Kit 翻譯完成的實際毫秒數；**不含聲音到 ASR 轉文字的時間**，不能錯誤解釋成全流程延遲。
6. 原本 NFC、Nearby、多檔傳輸、手勢、手動退出主 App、長按／拖曳「譯」懸浮小球、OCR 備用、英文／日文離線模型及繁體中文處理均保留。
7. v1.0.36，versionCode **49**，正式原簽章、`tw.airgesture.transferbeta` 套件 ID 不變；ARM64 APK 針對 S26 Ultra／S25。CI 驗證原簽章、ABI 與新增語音增量辨識測試。

## 測試
1. 保留原資料覆蓋更新 1.0.36，英文或日文設為來源，**語音優先**開啟。
2. 不用開字幕或框選，播放有人持續對話的 YouTube 影片，比較 v1.0.35 的中文字幕出現速度。
3. 測「I know, it's good」、短句及動漫短句。留意中文字幕是否較早出現、是否會頻繁改字。
4. 用「譯」球→「檢查字幕畫面」查看語音狀態；或在首頁字幕診斷看「語音翻譯耗時」。如語音完成前仍等很久，瓶頸可能在 Vosk 語音辨識；若翻譯耗時很長，則在 ML Kit 翻譯或裝置負載。
5. 切換影片、橫直向旋轉、暫停／恢復，確認沒有殘留舊字幕或永久停止辨識；遊戲三開時檢查發熱與耗電。
6. 主 App 依舊只在按「返回桌面 · 開始使用」時最小化，NFC／Nearby 傳檔和手勢測試不能受影響。

## 限制
本版的較短輪詢時間並不表示畫面絕對延遲 520–750 ms。加上 Vosk 模型還需要聲音片段、手機 CPU 處理、ML Kit 中文翻譯及播放內容本身的允許擷取情況。更快暫時結果可能偶爾先顯示粗略譯文、再被完整句修正；翻譯品質與速度仍需 S26 Ultra 實機回歸。並非所有串流 App 都允許 Android 第三方 PlaybackCapture。
